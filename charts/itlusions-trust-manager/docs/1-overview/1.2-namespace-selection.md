# 1.2 Namespace selection

The separate `itlusions-cert-ca` chart creates the `itlusions-internal-trust` Bundle when
`trustBundle.enabled` is `true`. Its values select where trust-manager writes the public
root CA, in a ConfigMap named `itlusions-internal-trust` with a `ca.crt` key. The
trust-manager chart itself does not configure this Bundle.

## Select namespace names

Set the following in a values file for the **CA chart**:

```yaml
trustBundle:
  enabled: true
  namespaces:
    - cert-manager
    - keycloak
    - operators
    - my-app
```

This selects namespaces by their Kubernetes `kubernetes.io/metadata.name` label. The
default list is `cert-manager`, `keycloak`, and `operators`; add or remove names as
needed. Each selected namespace must exist before its ConfigMap can be created. An empty
list is rejected when no custom selector is configured.

## Select all namespaces

To distribute the public root to all namespaces, including future namespaces, use a
selector that matches Kubernetes' automatically assigned namespace-name label:

```yaml
trustBundle:
  enabled: true
  namespaceSelector:
    matchExpressions:
      - key: kubernetes.io/metadata.name
        operator: Exists
```

This non-empty selector replaces the namespace-name list. It also selects system
namespaces such as `kube-system`; use it only if distribution there is intended.
trust-manager must have permission to write targets in every selected namespace. Its
upstream `app.targetNamespaces` setting, if configured, can limit those targets.

An empty `namespaceSelector: {}` does **not** select all namespaces in the ITlusions CA
chart: it falls back to `trustBundle.namespaces`.

## Exclude namespaces

To select all namespaces except specific names, combine the namespace-name label check
with a `NotIn` expression:

```yaml
trustBundle:
  enabled: true
  namespaceSelector:
    matchExpressions:
      - key: kubernetes.io/metadata.name
        operator: Exists
      - key: kubernetes.io/metadata.name
        operator: NotIn
        values:
          - kube-system
          - kube-public
          - kube-node-lease
```

Apply these values to the CA chart. New namespaces are selected automatically unless
their names appear in the exclusion list. The selector replaces `trustBundle.namespaces`.
After changing a selector, check whether any previously created ConfigMaps remain in
excluded namespaces.

## Select namespace labels

Alternatively, set a custom selector in the CA chart values:

```yaml
trustBundle:
  enabled: true
  namespaceSelector:
    matchLabels:
      itlusions.io/trust-internal-pki: "true"
```

Label each namespace that should receive the root:

```powershell
kubectl label namespace my-app itlusions.io/trust-internal-pki=true
```

A non-empty `namespaceSelector` replaces `trustBundle.namespaces`; it does not add to
the namespace-name list. For example, label `cert-manager`, `keycloak`, and `operators`
as well if they should continue receiving the bundle. Kubernetes `matchExpressions`
are also supported. Restrict who can label namespaces because the selector determines
where the public CA is distributed.

## Apply the configuration

Pass the values file when installing or upgrading the **`itlusions-cert-ca`** Helm
release, not the trust-manager release. Preserve the release's other required values
when doing so.

For persistent CLI deployments, add the values file to the CA chart entry in the active
profile. For example, place `ca-trust-values.yaml` beside the profile and include:

```yaml
helmCharts:
  # Other chart entries remain unchanged.
  - name: itlusions-cert-ca
    path: ../../../charts/itlusions-cert-ca
    namespace: cert-manager
    createNamespace: false
    valuesFiles:
      - ca-trust-values.yaml
    values:
      trustBundle.enabled: true
```

`valuesFiles` paths are relative to the profile file. Keep the existing chart order and
other required profile settings, and rerun the deployment using that profile. Chart entry
`values` are passed as Helm `--set` arguments after values files and therefore take
precedence over the same settings in the file.

## Verify distribution

Check the Bundle condition and target selector:

```powershell
kubectl describe bundle itlusions-internal-trust
kubectl get bundle itlusions-internal-trust -o yaml
```

Check the ConfigMap in each selected namespace:

```powershell
foreach ($ns in @('cert-manager', 'keycloak', 'operators')) {
    kubectl -n $ns get configmap itlusions-internal-trust
}
```

For an all-namespaces selector, list matching ConfigMaps across the cluster:

```powershell
kubectl get configmaps -A --field-selector metadata.name=itlusions-internal-trust
```

Use the appropriate Kubernetes context for your cluster. `Synced=True` and the presence
of the ConfigMaps show distribution, not whether an application has loaded or trusts the
CA. These ConfigMaps contain public CA certificates, not CA private keys or issued
application certificates.
