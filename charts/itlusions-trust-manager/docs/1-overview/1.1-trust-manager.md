# 1.1 itlusions-trust-manager

The [itlusions-trust-manager chart](../../) installs trust-manager v0.26.0 as a separate
Helm release alongside cert-manager. Install cert-manager first and wait for its CRDs and
webhook to be ready; trust-manager uses cert-manager to issue its own webhook certificate.
This chart does not install a CA or create a `Bundle`.

In the ITlusions kind profile, this release is installed between cert-manager and the
separate `itlusions-cert-ca` chart. The CA chart can create the `itlusions-internal-trust`
Bundle, which distributes the public root certificate to ConfigMaps in selected namespaces.
See [namespace selection](1.2-namespace-selection.md) for configuration and verification.

There is no custom readiness hook. Helm waits for the release, but a ready Deployment
does not guarantee that the admission webhook is reachable. If the following CA release
fails because the webhook is not yet reachable, retry the deployment when trust-manager
is ready.

Run from the root of the `ITL.Helm.Charts` repository:

```powershell
helm dependency build .\charts\itlusions-trust-manager
helm lint .\charts\itlusions-trust-manager
helm upgrade --install itlusions-trust-manager .\charts\itlusions-trust-manager --namespace cert-manager --wait --timeout 10m
```

The trust namespace defaults to `cert-manager`. The upstream controller can read Secrets
in this namespace, including private keys; restrict access to the controller and review
its RBAC for production. The ITlusions Bundle targets ConfigMaps containing public
certificates; Secret targets are disabled by default. Synchronizing a ConfigMap does not
automatically configure applications, the Kubernetes API server, or host truststores.
Plan CA rotation with overlap between the old and new public roots.

See the [upstream documentation](https://cert-manager.io/docs/trust/trust-manager/) and
the separate ITlusions CA chart documentation for Bundle configuration.
